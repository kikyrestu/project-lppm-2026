Dokumentasi Antarmuka Programming (API)

Dokumen ini menjelaskan seluruh endpoint backend Sistem Informasi LPPM. Setiap endpoint disertai kontrak permintaan, kode respons, contoh nyata, dan catatan keamanan. Endpoint yang sudah diuji end-to-end ditandai Terverifikasi; sisanya masih dalam pengerjaan dan ditandai Rencana agar tidak disalahartikan sebagai fitur yang sudah tersedia.

Konvensi umum

Seluruh endpoint memakai satu bentuk respons yang sama, sehingga klien cukup memeriksa field ok untuk menentukan alur.

Sukses
{ "ok": true, ...data }
Gagal
{ "ok": false, "code": "...", "message": "..." }
Aturan yang berlaku
  • Semua body permintaan memakai Content-Type: application/json.
  • Validasi memakai Zod; kegagalan validasi menghasilkan 400 VALIDATION beserta daftar pesan per field.
  • Sesi dikirim sebagai cookie httpOnly, sehingga token tidak dapat dibaca script di browser.
  • Masa berlaku sesi 8 jam; setelah itu permintaan menghasilkan 401 SESSION_INVALID dan cookie dibersihkan otomatis.
  • Password disimpan sebagai bcrypt cost 10 dan tidak pernah dikembalikan dalam bentuk apa pun.

POST/api/auth/loginTerverifikasiTidak perlu (publik)

Autentikasi pengguna dengan NIDN dan password.

Body permintaan
FieldTipeWajibKeterangan
nidnstringya1–20 karakter. NIDN dosen/pegawai.

Kode respons
StatusArti
200Login berhasil. Cookie `lppm_token` (httpOnly, path=/) disetel.
400Body tidak lolos validasi Zod.
401NIDN tidak dikenal ATAU password salah.
403Kredensial benar tetapi akun berstatus NONAKTIF.
Contoh
Permintaan
{"nidn": "9999999001", "password": "LppmDemo123!"}
Respons sukses
{
  "ok": true,
  "message": "Login berhasil",
  "user": {
    "id": "a779dadb-caa3-4ac6-82a4-55dd07405de8",
    "nidn": "9999999001",
    "nama": "Admin LPPM",
    "roles": ["ADMIN"],
    "programStudi": { "kode": "TI", "nama": "Teknik Informatika" }
  }
}
Respons kegagalan
{
  "ok": false,
  "code": "UNAUTHORIZED",
  "message": "NIDN atau password salah"
}
Catatan
  • Pesan kegagalan **sengaja dibuat sama** untuk NIDN tak dikenal dan password salah, agar akun tidak bisa ditebak keberadaannya (user-enumeration).
  • Bcrypt tetap dijalankan memakai hash dummy ketika NIDN tidak ditemukan, sehingga waktu respons identik (mencegah pembocoran lewat timing).
  • Cookie bersifat httpOnly sehingga token tidak dapat dibaca script browser akibat XSS.
